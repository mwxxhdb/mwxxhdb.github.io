# 阮一峰行文风格

从阮一峰博客 97 篇原创文章（22.9 万字，2005–2026 年，已剔除译文、转载与英文摘录）中量化提炼。
所有数值均为实测频率，不是印象。

## 何时用

适合：技术教程、工具/方案分享、技术观点、科普解释。
不适合：API 参考文档、变更日志、需要严谨措辞的规范文本。

**学的是结构与节奏，不是内容**。不要照搬他的句子、例子或段落——那是抄袭，不是风格。

## 最鲜明的三个特征

按重要性排序。只做到这三条，就已经像了七成。

### 1. 段落极短，六成是单句成段

实测：平均 **56 字/段**，中位 46 字，**61% 的段落只有一句话**。

这是最容易被忽略、也最决定观感的一条。不要写三五句话的「标准段落」，
一个意思说完就换行。视觉上大量留白，读者不会有压迫感。

```
✅ 这样写

Rollup 是一个 JavaScript 模块打包器。

它的特点是只做打包，不做转换。

如果你需要转换，要自己配置插件。

❌ 不要这样

Rollup 是一个 JavaScript 模块打包器，它的特点是只做打包而不做转换，
如果你需要转换的话，就要自己配置相应的插件来完成这项工作。
```

**但别切过头。** 段落碎到极致会变成断续的短句流，读起来同样累。
下面是 96 篇逐篇统计后的分布，写完可以量一下自己落在哪。

| 指标 | 合理区间（P25–P75） | 中位 | 过头的信号 |
|---|---|---|---|
| 段均字数 | **46–67 字** | 55 | < 42 字（低于 P10） |
| 单句成段占比 | **45–72%** | 60% | > 79% |
| 平均句长 | **32–38 字** | 35 | < 28 字 |

区间比想象中宽——他并不是每段都只写一句，而是**单句段和双句段交替**，
靠这个错落产生节奏。整篇都是单句段，反而不像。

**不要靠数「连着几段是单句」来判断。** 这个直觉是错的——实测 68% 的文章里出现过
连续 3 段以上的单句段，每篇的最长连续段中位数就有 4 段，最长的一篇连着 19 段。
连续单句段是他的常态，不是毛病。

真正的信号是**段均字数**。他那些连着 5 段以上单句的地方，段落本身平均只有 38 字，
明显短于全文的 56 字——那是刻意的短促排比，用来加快节奏。

所以判断标准只有一条：段均字数掉到 42 以下，就是切碎了。
段均落在区间内的话，连着七八段都是单句也无所谓。

> 自己量的时候注意：**代码块和 shortcode 要当作段落分隔符**，不能直接删掉再统计。
> 删掉的话，原本被代码块隔开的两段会变成相邻，得出错误结论。

### 2. 连接词单独起段，后面跟逗号

实测高频段首：`但是，`（44 次）、`所以，`（24）、`然后，`（21）、`首先，`（17）、`注意，`（16）。

转折和推进不藏在句子中间，而是**放在新段落的开头**，后面立刻跟一个逗号。
这是他文章节奏感的主要来源。

```
✅  但是，这个方法有一个问题。

❌  但是这个方法存在着一定的问题。
```

### 3. 结尾写「（完）」

实测 **93/97 篇**（96%）以 `（完）` 单独成行结尾。

不写「总而言之」「希望本文对你有帮助」这类总结。说完最后一个点，
空一行，写 `（完）`。技术教程可以在此之前加一节「参考链接」列表。

## 结构

- **篇幅**：篇均 2285 字。教程类可到 4000+，随笔 1000 上下。
- **小标题**：平均每篇 3 个，**81% 用「一、二、三」中文数字编号**。
  标题本身要短，多为名词或动宾短语：`一、引言` `二、安装` `三、基本用法`。
  有时只写 `一、` `二、` 而不带文字，纯粹用来分段。
- **开头**：第一句就进正文，三种常见开法——
  1. 直述现象：`越来越多的网站，开始采用"单页面结构"。`
  2. 交代来由：`前几天读到一篇文章，它提到……我顿时有一种醍醐灌顶的感觉。`
  3. 声明本文任务：`本文详细介绍它的用法。`

  绝不写「在当今互联网时代」「随着技术的发展」这类铺垫。

## 句子

| 指标 | 实测值 |
|---|---|
| 平均句长 | 32.9 字 |
| 中位句长 | 29 字 |
| 短句（≤15 字） | 18% |
| 长句（>45 字） | 22% |

**多用逗号切分**。一个长句拆成几个短分句，用逗号连成一串，而不是用从句套从句。

```
✅  飞机有四个引擎，如果一个引擎坏了，剩下三个引擎，还能继续飞，这就是"容错"。
```

## 用词与标点（每万字频率）

| 项目 | 频率 | 说明 |
|---|---|---|
| 「我」 | 30.9 | 第一人称，大方给出个人判断 |
| 「你」 | 21.5 | 直接称呼读者，像当面讲解 |
| 括号（） | 40.6 | 补充说明、给英文原词、加注解 |
| 双引号 | 48.1 | 标记术语和新概念的**首次出现** |
| 冒号 | 25.8 | 引出解释和列举 |
| 问号 | 9.8 | 设问推进，自问自答 |
| 感叹号 | 1.7 | **极少用**，克制情绪 |

关键习惯：**新术语第一次出现时，用双引号标出，并在括号里给英文原词**。

```
✅  这种做法叫做"容错"（fault tolerance）。
```

## 解释手法（每万字频率）

- 解释因果 7.2、举例 5.9、顺序词 9.0、换句话说 1.8、类比 1.3

讲清楚一个概念的套路是固定的：**下定义 → 举生活化的例子 → 点出适用边界**。

例子优先用日常事物（飞机引擎、汽车轮子），而不是又一个抽象概念。

口语化但不油腻：`其实` `真的` `一下` 都是低频出现（每万字 1–4 次），
点到为止。不用网络流行语，不用「家人们」「绝绝子」这类腔调。

## 自检清单

写完后逐条对照：

- [ ] 有没有超过 3 句话的段落？拆开。
- [ ] 段均字数落在 46–67 字吗？低于 42 就是切碎了（别去数连续单句段，那个指标没用）。
- [ ] 转折词是不是藏在句中？提到段首去。
- [ ] 小标题是不是「一、二、三」编号？
- [ ] 新术语首次出现有没有加引号和英文原词？
- [ ] 有没有出现「总而言之」「综上所述」「希望对你有帮助」？删掉。
- [ ] 感叹号是不是超过两个？减掉。
- [ ] 结尾是不是 `（完）`？

## 与本仓库 CLAUDE.md 的关系

`CLAUDE.md` 定义的是**底线**（禁 AI 腔、要具体、读者是同行工程师），任何时候都适用。
本 skill 是在此之上的**可选风格模板**，两者不冲突——阮一峰的写法本身就满足那些底线。

冲突时以 `CLAUDE.md` 为准，尤其是读者定位：本站读者是后端/平台工程师，
不需要把基础概念解释得像面向大众的科普。
